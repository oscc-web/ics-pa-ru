### Использование Git

<!-- We will use the `branch` feature of `git` to manage the process of development.
A branch is an ordered list of commits, where a commit refers to some modifications in the project.

You can list all branches by -->

Мы будем использовать возможность `branch` в `git`, чтобы управлять процессом разработки.
Ветка — это упорядоченный список коммитов, где коммит относится к некоторым изменениям в проекте.

Вы можете перечислить все ветки командой
```
git branch
```
<!-- You will see there is only one branch called "master" now. -->

Вы увидите, что сейчас есть только одна ветка с именем "master".
```
* master
```
<!-- To create a new branch, use `git checkout` command: -->

Чтобы создать новую ветку, используйте команду `git checkout`:
```
git checkout -b pa0
```
<!-- This command will create a branch called `pa0`, and check out to it.
Now list all branches again, and you will see we are now at branch `pa0`: -->

Эта команда создаст ветку с именем `pa0` и переключится на неё.
Теперь снова перечислите все ветки, и вы увидите, что сейчас мы на ветке `pa0`:
```
  master
* pa0
```
<!-- From now on, all modifications of files in the project will be recorded in the branch `pa0`.

Now have a try!
Modify the `STUID` and `STUNAME` variables in `ics2023/Makefile`: -->

С этого момента все изменения файлов в проекте будут записываться в ветку `pa0`.

Теперь попробуйте!
Измените переменные `STUID` и `STUNAME` в `ics2023/Makefile`:
```
STUID = 221220000  # ваш студенческий ID
STUNAME = 张三     # ваше китайское имя
```
<!-- Run -->

Выполните
```
git status
```
<!-- to see those files modified from the last commit: -->

чтобы увидеть файлы, изменённые с последнего коммита:
```

Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git checkout -- <file>..." to discard changes in working directory)

	modified:   Makefile

no changes added to commit (use "git add" and/or "git commit -a")
```
<!-- Run -->

Выполните
```

```
<!-- to list modifications from the last commit: -->

чтобы перечислить изменения с последнего коммита:
```diff

@@ -1,4 +1,4 @@

<!-- You should see `STUID` and `STUNAME` are modified.
Now add the changes to commit by `git add`, and issue `git commit`: -->

Вы должны увидеть, что `STUID` и `STUNAME` изменены.
Теперь добавьте изменения в коммит через `git add` и выполните `git commit`:
```

git commit
```
<!-- The `git commit` command will call the text editor.
Type `modified my info` in the first line, and keep the remaining contents unchanged.
Save and exit the editor, and this finishes a commit.
Now you should see a log labeled with your student ID and name by -->

Команда `git commit` вызовет текстовый редактор.
Наберите `modified my info` в первой строке и оставьте остальное содержимое без изменений.
Сохраните и выйдите из редактора — это завершит коммит.
Теперь вы должны увидеть журнал, помеченный вашим студенческим ID и именем, командой
```

```
<!-- Now switch back to the `master` branch by -->

Теперь переключитесь обратно на ветку `master` командой
```
git checkout master
```
<!-- Open `ics2023/Makefile`, and you will find that `STUID` and `STUNAME` are still unchanged!
By issuing `git log`, you will find that the commit log you just created has disappeared!

Don't worry! This is a feature of branches in `git`.
Modifications in different branches are isolated,
which means modifying files in one branch will not affect other branches.
Switch back to `pa0` branch by -->

Откройте `ics2023/Makefile`, и вы обнаружите, что `STUID` и `STUNAME` по-прежнему не изменены!
Выполнив `git log`, вы обнаружите, что журнал коммита, который вы только что создали, исчез!

Не волнуйтесь! Это возможность веток в `git`.
Изменения в разных ветках изолированы,
то есть изменение файлов в одной ветке не затронет другие ветки.
Переключитесь обратно на ветку `pa0` командой
```
git checkout pa0
```
<!-- You will find that everything comes back!
At the beginning of PA1, you will merge all changes in branch `pa0` into `master`.

The workflow above shows how you will use branch in PAs:
* before starting a new PA, new a branch `pa?` and check out to it
* coding in the branch `pa?` (this will introduce lot of modifications)
* after finish the PA, merge the branch `pa?` into `master`, and check out back to `master` -->

Вы обнаружите, что всё вернулось!
В начале PA1 вы вольёте все изменения из ветки `pa0` в `master`.

Рабочий процесс выше показывает, как вы будете использовать ветки в PA:
* перед началом нового PA создайте ветку `pa?` и переключитесь на неё
* пишите код в ветке `pa?` (это внесёт много изменений)
* после завершения PA вольйте ветку `pa?` в `master` и переключитесь обратно на `master`

> #### danger::отслеживание разработки
> Мы используем `git`, чтобы отслеживать ваши эксперименты, и плохое отслеживание повлияет на оценку.
> Предыдущий студент «выполнил» раздел лабораторной, но мы не смогли найти для него git log, и раздел был сочтён невыполненным.
> git log — самое сильное доказательство самостоятельного выполнения эксперимента, а выполнение эксперимента без нормального git log
> не только лишит вас многих баллов, но и даст самое сильное доказательство плагиата.
> Поэтому обратите внимание на следующее.
